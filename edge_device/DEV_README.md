# Dev Environment Setup

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed and running
- A clangd-based editor (Neovim, VS Code with clangd extension, CLion, etc.)

That's it. You do **not** need to install the Azure IoT SDK, CMake, or any C++ toolchain on your host machine. Everything builds and runs inside Docker.

## First-Time Setup

```bash
chmod +x setup.sh
./setup.sh
```

This script does two things:

1. **Pulls headers out of the Docker builder image** into `external/include/` so your editor's LSP can resolve Azure IoT SDK symbols.
2. **Generates `compile_commands.json`** with absolute paths for your machine so clangd knows how to build each file.

Both `external/` and `compile_commands.json` are gitignored — run `setup.sh` once after cloning, and again if you add new source files or the Dockerfile changes.

## Building and Running

```bash
# Build the Docker image and run the device simulator
docker compose up --build

# Or without compose
docker build -t edge-device .
docker run --rm edge-device
```

## Editor Setup (Neovim + clangd)

After running `setup.sh`, open any `.cpp` or `.hpp` file in Neovim. clangd will automatically pick up `compile_commands.json` from the project root. No additional configuration needed.

If you see LSP errors on first open, wait ~10 seconds for clangd to finish background indexing, then run `:LspRestart`.

## Adding New Source Files

1. Add the `.cpp` file to `CMakeLists.txt` under `add_executable`.
2. Add the filename to the `SOURCES` array at the top of `setup.sh`.
3. Re-run `./setup.sh` to regenerate `compile_commands.json`.

## .gitignore

The following are intentionally not committed:

```
external/        # headers extracted from Docker — regenerated by setup.sh
compile_commands.json  # has absolute paths, machine-specific
build/           # build artifacts
```
